Scaling

Better answers without retraining.

ITS improves model accuracy at inference time by generating and evaluating multiple candidate responses. Enterprise customers on OpenShift AI can apply ITS to any model via a header or API parameter, getting better answers without touching model weights.

Market Context

Every major provider has shipped thinking budget controls.

OpenAI (5 effort levels), Google (4 thinking levels + dynamic mode), Anthropic (5 effort levels), DeepSeek (3 modes), NVIDIA (token-level budget control). The market has validated that inference-time compute scaling is a real product capability, not a research curiosity.

The gap is infrastructure-level ITS. Every provider's implementation is model-level: baked into one specific model, controlled by that provider's API. Customers who want ITS on their own models, on their own infrastructure, with their own data, have no production option. Red Hat fills that gap.

How It Works

LLMs are stochastic. The same prompt produces different answers every time. Single-shot inference is rolling the dice once. ITS rolls multiple times, then picks the best result.

THE PROBLEM

Every question gets one attempt, same compute regardless of difficulty. Hard questions fail not from ignorance but from rushing.

→

THE INSIGHT

Models produce the correct answer in their top N responses. They just don't always give it on the first try.

→

THE RESULT

10 to 30% accuracy gains across domains. Same model, same weights. $0 retraining cost. Just more thinking.

The Problem

Hard questions get the same compute as easy ones

  • ✕ Training is expensive, slow, and difficult to iterate on
  • ✕ Single-shot inference is unreliable for high-stakes decisions
  • ✕ Agentic tool calling fails silently: one bad call cascades
  • ✕ Disconnected environments cannot reach frontier APIs
The Solution

Trade inference compute for accuracy

  • ✓ Generate N candidate responses in parallel
  • ✓ Evaluate and select the best result
  • ✓ No retraining, no fine-tuning, no model changes
  • ✓ Works with any OpenAI-compatible model

Algorithms

ITS Hub provides multiple algorithms, each approaching the same problem from a different angle. Self-Consistency is the default starting point; the others excel in specific scenarios. All share the same interface, so switching between them is a one-line code change.

Self-Consistency

Generate N responses, majority vote on answer. Supports hierarchical tool voting.

Best for: factual questions, classification, tool calling

Best-of-N

Generate N candidates, score with a reward model or LLM-as-judge, select the highest-scoring response.

Best for: open-ended generation, quality-sensitive tasks

Beam Search

Step-by-step generation with beam width control. Process reward models guide the search at each step.

Best for: multi-step reasoning, math, logic

Particle Filtering

Probabilistic resampling to maintain diverse reasoning paths while focusing on promising directions. Includes Entropic PF and Particle Gibbs variants.

Best for: complex multi-step problems, tool calling

Frequently Asked Questions

Common questions about inference-time scaling and how to adopt it.

What’s the difference between ITS and model fine-tuning?

ITS requires $0 retraining and works with any model. You get better answers by generating and evaluating multiple responses at inference time — no weight changes, no training data, no GPU hours for fine-tuning. Fine-tuning is model-specific, expensive to iterate on, and locks you into a single model version. ITS is complementary: you can fine-tune a model and then apply ITS on top for additional gains.

Which algorithm should I start with?

Self-Consistency for most tasks. It requires no reward model, works out of the box, and handles factual questions, classification, and tool calling well. Use Best-of-N when you have a reward model or LLM-as-judge and need quality scoring rather than majority agreement. See the algorithm cards in the How It Works section for detailed comparisons.

What’s the compute overhead?

N=8 means 8x inference compute, but 0x training compute. The trade is often favorable for high-stakes decisions where a wrong answer costs more than a slow one. Candidates are generated in parallel, so wall-clock latency scales sub-linearly. The compute budget is a runtime configuration choice — you can set N=2 for low-stakes queries and N=16 for critical ones.

Can ITS work with our existing model endpoint?

Yes, if it’s OpenAI-compatible. ITS is infrastructure-level, not model-level — it sits between your application and any model server that speaks the OpenAI Chat Completion API. That includes vLLM, TGI, OpenAI, and any compatible endpoint. No model changes or special model versions required.

How do we get started?

Two paths: install its-hub via pip for the Python SDK, or deploy the upstream gateway for transparent HTTP-level scaling. Both are available today. See the How to Use section for quick-start code, architecture diagrams, and deployment options.
