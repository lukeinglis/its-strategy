Strategy Overview

Inference-Time
Scaling

Better answers without retraining.

ITS improves model accuracy at inference time by generating and evaluating multiple candidate responses. Enterprise customers on OpenShift AI can apply ITS to any model via a header or API parameter, getting better answers without touching model weights.

How It Works

Your models already know the answer. They just don't always give it to you on the first try.

The Problem

Errors come from underthinking, not lack of knowledge

  • ✕ Hard questions get the same compute as easy ones
  • ✕ Single-shot inference is rolling the dice once
  • ✕ Tool calling (agents) fails silently: one bad call cascades
  • ✕ 55 to 80% of GPU spend is inference, not training
[Prompt] → [Model] → [Answer ?]
The Solution

Generate N responses. Evaluate each one. Select the best.

  • ✓ Trade inference compute for accuracy: a knob you can turn
  • ✓ No retraining, no fine-tuning, no model changes
  • ✓ Works with any OpenAI-compatible model endpoint
  • ✓ Applied as infrastructure, not baked into one model
[Prompt] → [Model × N] → [Evaluate] → [Best Answer ✓]

Algorithms

Self-Consistency

Generate N responses, majority vote on answer.

Best for: factual questions, classification, structured output

Best-of-N

Generate N responses, score with reward model or LLM-as-judge, pick best.

Best for: open-ended generation, quality-sensitive tasks

Beam Search

Explore multiple reasoning paths step-by-step, prune weak branches.

Best for: multi-step reasoning, math, logic

Particle Filtering

Probabilistic search with resampling at each step.

Best for: complex multi-step problems, tool calling

Hierarchical Voting

Two-stage: cluster similar answers, then vote across clusters.

Best for: high-variance tasks, diverse answer spaces

Strategic Initiatives

Four workstreams extending ITS from SDK to platform-wide capability.

ITS Gateway

In Progress

ITS as an Envoy ext-proc filter in the Red Hat AI Gateway. Apply inference-time scaling to any model via a header or API parameter. No code changes required.

Lead: Yi Zheng

Target: 3.4 (V2 modularization), 3.5 (Envoy ext-proc)

Jira: RHAISTRAT-1062, RHAISTRAT-178

ITS for Tool Calling

In Build

Voting over parallel tool call candidates. Makes smaller, local models viable for agentic tasks by compensating for lower baseline accuracy.

Lead: Giorgio Giannone

Target: 3.5 (Q3 2026)

Validation: OpenShift Lightspeed, MCP integration

Elastic ITS

Approved

Compute-aware mode that uses idle GPU capacity for net-neutral accuracy improvement. When spare compute is available, ITS runs more candidates; when constrained, it falls back gracefully.

Lead: Yi Zheng

Status: Approved RFE, not yet started

Jira: RHAISTRAT-179

Beyond Verifiable Domains

Research

Extending ITS to domains without a ground-truth verifier: healthcare, security, planning, advisory. Rubric-conditioned scoring replaces the oracle.

Lead: Giorgio Giannone

First proving ground: Healthcare (HealthBench)

Key result: +0.185 on emergency referrals with ePF at budget 8
